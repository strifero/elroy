# Chapter 7: Teaching it to answer

By the end of this chapter Elroy replies to "write a function that checks whether a number is prime" with a function that checks whether a number is prime, says who it is when asked, and stops talking when it is done. The base model could do none of those things, and the change takes a few hours of fine-tuning on a single GPU.

## Why a base model does not answer questions

Pretraining teaches the model to continue text. Give it `def is_prime(n):` and it writes a body, because files that start that way continue that way. Give it `Write a function that checks whether a number is prime.` and it continues with whatever tends to follow that sentence in the corpus: another sentence, a list of requirements, sometimes code, often nothing useful, and it never stops. The knowledge is there. The format is not.

Supervised fine-tuning shows the model a few tens of thousands of conversations laid out in one fixed template and trains it to produce the reply part. It learns three things: the template means a question is being asked, the reply should be an answer, and `<|end|>` means stop.

## The template

```
<|system|>You are Elroy, a small Python assistant built from scratch by Strife Technologies.<|end|>
<|user|>{question}<|end|>
<|assistant|>{answer}<|end|><|endoftext|>
```

`elroy/chat.py` has it in one place, `build_prompt`, used identically for training data and for inference. The special tokens were reserved in the tokenizer in Chapter 2 so they are single ids the model has never seen in pretraining; it learns them from scratch here.

## The data

```bash
python scripts/prepare_sft.py --tokenizer data/tokenizer.json --out data/sft
```

Two public sets, both permissively licensed: Magicoder OSS-Instruct (75k problems generated from real open-source snippets, MIT) and evol-codealpaca-v1 (111k Evol-Instruct tasks, Apache-2.0). The script keeps examples whose reply has a Python code block that parses under Python 3 and fits in 2048 tokens; that keeps 96% of OSS-Instruct's Python and about 39% of evol-codealpaca, since the rest is other languages.

Plus `sft/handwritten.jsonl`: 45 examples we wrote, repeated four times. Who Elroy is, what it cannot do, a dozen beginner concepts, a dozen small functions. Every base model fine-tuned only on scraped data believes it is ChatGPT; this is the cheap fix. The file is generated by `sft/make_handwritten.py` so the source of truth is readable Python, and every code block in it is checked with `ast.parse`.

### Loss masking

`format_example` returns the token ids and a mask that is 0 over the system and user text and 1 over the reply and its `<|end|>`. `Elroy.forward` takes that mask and averages the loss over the 1s only. The model is never trained to predict the question, only the answer. Without this, a third of the gradient goes into learning to write user prompts, which is both wasted and slightly harmful.

## Training

```bash
python -m elroy.sft --base checkpoints/elroy-350m/latest.pt --data data/sft --out checkpoints/elroy-350m-chat
```

Same model class, same optimizer, same bf16 autocast. Differences from pretraining: learning rate 5e-5 instead of 4e-4 (the weights are good; we are nudging, not carving), two epochs, no weight decay, batches drawn from length buckets so that padding to the longest example in a batch wastes little.
